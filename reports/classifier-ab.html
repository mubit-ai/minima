Does the embed head earn its place?

A pre-registered A/B of the shipped static-embedding task classifier against the regex it replaced, on benchmark data it was never trained on.

On out-of-corpus benchmark data the shipped head is significantly worse than the regex it replaced. Three remedies were pre-registered and tested. All three failed.

KEEP ✕ Fails. The confidence interval lies entirely below zero.
RETUNE ✕ Falsified in round 2. The best reachable operating point on the abstention frontier is Δ = +0.0045, 95% CI [−0.0073, +0.0170] — indistinguishable from deleting the head. Details.
ROUTE ✕ Class-competence routing does not rescue it either. Δ = −0.0595, CI [−0.0845, −0.0346]. Every deny-set variant loses.
PULL ⚠ Both clauses now met on this evidence, but still not dischargeable: the downstream leg is blocked by evaluation infrastructure, and code — plausibly the highest-traffic type — has no gold here.

What the evidence supports today: the head contributes nothing measurable over vocabulary+regex on out-of-corpus prose, and cannot be configured to. What it does not support is a final pull decision — 4 of 11 classes are unmeasured. The honest position is stop investing, measure code, then decide.

Finding 01

regex_hint is dead code for this artifact

Inspecting head.npz before any evaluation: regex_classes: [], regex_scale: 0.0, and coef is (11, 512) — exactly the embedding dims, no appended one-hot. classify_embed.py only concatenates the regex feature if self._regex_classes:, which is empty.

So the regex_hint passed at classify.py:572 is discarded on every call. Registered as a falsifiable prediction and confirmed: the with-hint and no-hint arms agree on 2,609 / 2,609 prompts, Δ = 0.0000.

Two consequences: the hint plumbing is wasted work on every classify, and the head's features are pure embeddings — so head-vs-regex is a fair comparison, not a model scored against its own input.

Finding 02

The gate suite is green while the head regresses

All 7 of 7 G1 gates pass against this artifact — including test_g1g_beats_regex_baseline and the G1e false-abstain bound — at the same time as the head loses 8.7 macro-F1 points to the regex.

G1g compares 118 rows with no confidence interval and no paired test. G1e passes at 1.8% measured false-abstain while real error is ~70%: the conformal calibration was fit on the training distribution and does not transfer. A green suite is currently not evidence that the head beats the regex.

Fixed in round 2 — and the root cause was worse than it looked. The suite had never run in CI: it carried the eval marker, and the CI job runs -m "not live and not eval". It is hermetic and costs 3 seconds, and the artifact was already committed, so the marker is gone and G1 now runs on every pull request — 550 passed, 1 xfailed, 6.5 s.

Also: the fixture called a hand-written mirror of the dispatcher rather than the dispatcher, so it could drift silently; G1g scored vocabulary+head against bare regex, crediting the vocabulary tier's wins to the head; and a new out-of-corpus gate (2,609 rows, content-hash pinned) lands as a strict xfail carrying Δ = −0.0865 — the suite stays green, the defect cannot be quietly deleted, and a retrain that fixes it forces the marker's removal. Honest footnote: the G1g baseline fix changed nothing numerically (+0.0000), because the vocabulary tier fires on 0.00% of that slice. The confound was structural, not outcome-changing.

Accuracy is a statistical tie — McNemar exact p = 0.49. The head is not making more mistakes; it is making differently distributed ones. The regex concentrates its correct answers in a few classes it fires on confidently and dumps 47% into other; the head commits everywhere and spreads errors across all eleven classes.

The error modes are semantically adjacent and operationally wrong

  • “rewrite a sentence in simple English”, “paraphrase the given sentence” → translation (94 rows)
  • “answer a simple science question” → reasoning (196 rows)
  • “recognize the name of the drug” → qa (77 rows)
  • It invents code on 171 rows where no code gold exists at all.

Churn is enormous: 74.3% of rows relabelled versus the regex, 59.6% among regex-non-other rows — 4× the review threshold in Minima's own churn_replay.py.

Ambiguity handling is worse, not better. On 198 deliberately unmappable prompts the regex routes 60.6% to other; the head routes 14.6% and abstains on 2.0%.

Two classifier-side explanations, tested and rejected

The 6.4× evidence-density gap is the obvious thing to blame on the head. It does not survive contact with the data.

The crosscheck failure is not the classifier

Hosted Mubit recall is non-deterministic: an identical query on an identical lane, repeated back-to-back, returned 16, 13, 16 evidence rows (and 1, 3, 7 on another lane). The V5 guard compares a pick made from recall cached once against a pick the engine makes from a fresh recall — so when the recalls differ, the picks differ, for reasons unrelated to what is being tested.

This blocks every downstream routing experiment, not just this one. It should be fixed before any further spend on downstream evaluation.

Pre-registration deviation, disclosed: the registered decision_basis == "memory" guard is not implementable on the path it was written for — the harness's headline runs through the factored scorer, which never constructs a response and so never produces that field. The applicable substitutes were used instead: evidence/model ≥ 8 (met, 11.7) and V5 ≥ 0.8 (failed, 0.50). My specification error, not a silent skip.

Consequence for the verdict: the PULL rule requires “Leg B shows no cost or quality gain”. Leg B shows nothing either way, so PULL cannot be discharged. Round 2 update: the RETUNE fallback recorded here was itself falsified, and the cause of this blocker was probed directly — it is not the classifier and not the bug it was attributed to. See below.

Round 2 · 2026-07-28

Retuning tested properly — and falsified

Round 1's retune claim rested on a point estimate with no confidence interval. Re-run with an honest calibration/held-out split and a paired bootstrap, it does not survive.

shipped τdist=0.8599, τmargin=0.00880.04598.7%0.2791
refit on a mixed calibration set, α=0.050.40998.2%0.2848

Three findings, each independently fatal to the retune path.

1. Refitting on a mixture barely moves the number and still loses by 7 points — while blowing G1e's false-abstain to 0.409, five times its 0.08 gate. Out-of-corpus calibration and the G1e bound are incompatible for this artifact.

2. The best reachable point, joint sweep selected on calibration and scored once on held-out: Δ = +0.0045, CI [−0.0073, +0.0170], P(Δ>0) = 0.765, at 15.6% coverage. Indistinguishable from deleting the head.

3. The unconstrained optimum is unreachable by construction. fit_joint_abstain_thresholds sweeps its distance quantile from 0.95 upward, and a higher threshold abstains less — so it can never express an operating point that abstains more than ~α. The optimum needs α ≥ 0.98.

On the in-corpus slice the head is fine: error among rows it commits on is 0.131. The ~70% error is purely out-of-corpus. This is a generalization failure, not a broken model. Nothing was shipped — derive_classifier_id hashes the artifact directory, so no τ can be swapped in silently.

I had the mechanism backwards. I argued the deny-set was what could move the number and the vocabulary-pattern variant was bounded and secondary. Inverted: every deny-set arm loses, and the only two arms reaching parity lean on the regex — one of which never calls the head at all. Their intervals overlap, so the ~+0.006 is the patterns, not the head.

The oracle arm being worse than the honestly-selected one is structural. A deny set chosen by comparing per-class F1 is blind to classes with no gold on the eval set — code, rag, tool_use, other have no F1 to compare, so they are never denied, and they are exactly where the head's false positives land. Pricing each class's system-level contribution directly: reasoning +0.0061, creative +0.0053, classification +0.0016 — against translation −0.0322, other −0.0241, rag −0.0175. Per-class F1 does not compose.

The A6′ patterns are genuinely high-precision — they fire on 16.4% of rows at 97.9% precision, meeting the vocabulary tier's near-zero-false-positive contract. They are an argument for improving the regex stack, not for keeping the head.

Round 2 · attribution

The downstream blocker is real — and it is not what it was blamed on

The hypothesis was that the recall instability matched a known, root-caused bug: a lane filter dropping untagged entries and falling through to a recency fallback with “a UUID-ordered, query-independent result set with a constant placeholder score of 0.5”. The dates bracket neatly. Every signature is absent.

Predicted by that bugObserved
constant score ≈ 0.524 distinct scores of 25, range 0.428–0.711
degenerate / absent semantic componentsemantic = 0.99, 0.99, 0.99, 0.99, 0.76 …
recency-ordered fallbackrank_by: "balanced", recency 0.0 throughout
query-independent results3 orthogonal queries, each 5/5 own-family in the top 5

What is actually broken. Five identical queries, same lane, same limit, index at rest: 0 of 10 pairs share an ordering, 4 distinct top-5 orderings across 5 calls, and 33 distinct entry ids at a limit of 25 — roughly a quarter of the result set churns per call.

The head of the ranking is stable and correct; the tail churns — exactly where evidence-per-model comes from once a fixed recall budget is split across N candidates, and exactly why the crosscheck guard (cached pick vs fresh pick) cannot reach its 0.80 floor. It measured 100% on 2026-06-12, so this is a regression, not a standing limit.

The pre-registered commitment was not to backfill an attribution from a date. It is not backfilled. No classifier change can unblock this guard, and the downstream leg stops here.

The dataset is the point. Super-NaturalInstructions — 2,609 labelled prompts, 437 tasks, 7 Minima types. It is in none of the head's training sources (curated seeds + CLINC150 + RouterBench). RouterBench cannot answer this question, because it is training data and its eval_name → task_type map is the same function that labelled those training rows.

Prod parity is exact. A live probe of api.minima.sh reproduces the local head on 100/100 prompts — including its failures. “Rewrite a sentence in simple English without changing its general meaning” returns final_task_type: translation, task_type_source: embedding, in production, right now.

The verdict is not an artifact of the gold map. Dropping the six categories flagged as most contestable widens the gap to −0.1166 [−0.1399, −0.0935].

Limitations

Read before acting

  • Register shift. The benchmark is instruction-manual prose (“In this task, you are given…”), not conversational user traffic — which is what the head's corpus deliberately targets. This is the strongest reason to read the result as “does not generalize to this distribution” rather than “bad everywhere”.
  • Coverage. The benchmark yields no reliable code, rag, tool_use or other gold. The verdict covers 7 of 11 types, and code — plausibly the highest-traffic type — is absent.
  • The 76→11 category map is ours, frozen and committed before any arm ran. Mitigated by the sensitivity analysis and per-category reporting, not eliminated.
  • Absolute numbers are not the point. Every arm scores badly here (~0.32 accuracy). The difference between arms is the quantity of interest.
  • Neighbour voting was never evaluated, and remains untested. It ships in the serving path, but it is gated on non-empty recall evidence — so it cannot be measured intrinsically at all; it needs live memory, which is precisely what is broken. Every verdict here is about the head, not about the serving configuration.
Next

Recommended actions

  • Stop investing in this artifact. Three pre-registered remedies — retune, class routing, and the regex-feature hypothesis — have all failed. Further tuning is not indicated.
  • Build the code-bearing set. It is the one piece of evidence that could change a pull decision, and 4 of 11 classes are unmeasured. Free sources exist (StackOverflow intents, issue statements); the cost is ~600 hand-labelled rows, 2–3 hours — or ~$5–15 for a label panel.
  • Land the new vocabulary patterns on their own merit. 16.4% fire rate at 97.9% precision, and they beat the head on every arm. Ship them as a regex improvement, not as a rescue for the classifier.
  • Fix hosted recall's top-k instability. Until then no routing experiment from this harness produces a defensible number, and neighbour voting stays untestable.
  • Delete the regex_hint plumbing — computed, passed, and discarded on every call.
  • If a retrain happens, target the attractors — → translation on paraphrase prompts, → reasoning on science questions, and the false-positive spray into the four classes with no gold, which is where the real system-level damage is.
  • Raise α or replace the threshold fitter if conformal abstention is kept at all — its grid cannot express an operating point that abstains more than ~α.
